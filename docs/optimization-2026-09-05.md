# 整体优化与验证记录（2026-09-05）

本次优化围绕调度正确性、停止与重启、结果存储和运行验证展开。
开始时工作区的已有修改已保留。对照版本为 Git 提交 `0d72b03`。
工作时间为北京时间约 14:10–15:10，持续一小时。

## 主要改动

- 即时请求与已满足运动条件的请求统一按优先级调度；及时收集同步调用结果，
  避免后续调用淘汰结果后把成功请求误判为失败。
- 设备完成通知只刷新相关服务；新请求入队不再触发全量结果轮询；
  无活动请求时调度线程等待事件，健康检查中的请求计数不再扫描完整历史。
- 修复取消、完成与历史清理之间的竞态；批量等待保护整组结果，
  取消设备操作时释放调度器状态锁，并正确处理同时到达的完成结果。
- 防止停止超时后的重叠重启，拒绝跨停止/重启过程准备的旧请求；
  支持调度和机器人状态回调主动停止自身，并处理并发的外部关闭。
- 轨迹复制与验证成功后才分配运动编号，编号分配与入队保持原子性；
  重启保留已完成编号和取消历史，主运动取消会传播给依赖它的外设请求。
- 线程池提交不再复制稀疏编号历史；结果回收仅操作已完成请求的堆，
  不扫描或取消仍在等待执行的请求。
- 同步任务保留失败响应、正确报告执行中的请求；停止打断零延迟重试，
  重启不会让旧调用恢复重试；遥测任务串行处理生命周期操作。
- 保留大整数参数边界的精度；隔离非法设备响应与不可 JSON 序列化的健康数据；
  加固网络示例的请求验证、关闭期间的请求接收和线程启动失败后的清理。
- 更新文档、基础/Viser 两种 CI 安装配置、线程异常检查和 wheel 安装验证。

## 使用时需要了解的行为

`ReducedRobotState` 新增默认值为空的 `cancelled_move_ids`，现有三参数构造仍然有效。
内置机器人停止后拒绝新运动，直到重新初始化；旧运动的取消状态不会被后续完成覆盖。

`stop(timeout=...)` 限制等待调度线程退出的时间。设备的停止钩子和 I/O 仍需设置自己的
超时；正在执行的 Python 回调依靠协作退出。结果清理会释放响应内容，任务的请求编号
去重历史仍然保留，稀疏编号会占用额外的标识符存储。

变更明细见 `CHANGELOG.md` 的 Unreleased 部分；常规使用方式见 `README.md`。
